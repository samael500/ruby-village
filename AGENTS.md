# Работа над Ruby Village

## Обязательный процесс

1. Каждое новое задание пользователя сначала оформить GitHub Issue. Если задание продолжает существующий тикет, обновить его, не создавать дубликат. Указать задачу и критерии готовности.
2. До изменения файлов создать отдельную ветку от актуальной `main`. В имени ветки по возможности указать номер Issue.
3. Выполнить работу и подходящие проверки. Создать Pull Request со ссылкой на Issue, описанием результата и проведённых проверок.
4. Каждый PR должен пройти ревью. Собственная проверка автора не заменяет ревью. Ответить на замечания и внести исправления до слияния.
5. Оставить PR открытым для ревью Максима, если он не назначил другого ревьюера. Не сливать PR без его явного разрешения и завершённого ревью.
6. Не делать прямые push в `main`. Не обходить PR ради публикации: GitHub Pages публикуется после слияния в `main`.
7. При завершении работы дать ссылки на Issue и PR и точно указать статус: готов к ревью, нужны исправления или слит. Issue закрывается после слияния PR, который выполняет критерии готовности; использовать `Closes #N` в описании такого PR.

Уточнения, обсуждения и ответы на вопросы сами по себе не требуют нового Issue, если не добавляют отдельную задачу. Не оформлять уже завершённые изменения задним числом без просьбы пользователя.
