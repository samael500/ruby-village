# Рубиновая деревня · Ruby Village

Первая глава сказочной головоломки для Ульяны и других детей 6–7 лет. Рута восстанавливает исчезнувшие дороги: от дома до калитки, вокруг сада и через реку к мельнице. Без таймера, очков и наказаний. Старый прототип доступен как **Песочница**.

**Играть:** https://maks.live/ruby-village/

## Запуск

Node.js 22.18+ (CI использует 24):

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

Открой напечатанный Vite адрес с `/ruby-village/`. Для телефона в одной сети используй сетевой адрес dev-сервера. Production — статические файлы TypeScript + Vite + SVG, без runtime-зависимостей и сервера приложения.

## Глава

На карте четыре места и три восстанавливаемые дороги. Первый уровень открыт сразу; следующие открываются последовательно. Пройденные уровни можно переигрывать.

- **До калитки, 7×5.** Диагональный маршрут от ступеней к калитке: уголок, двойная плита и один камешек. Две клетки под домом непроходимы.
- **В обход сада, 9×6.** Деревья и камни закрывают прямую дорогу; нужно выбрать формы для обхода. Одна фигура лишняя.
- **Переправа к мельнице, 11×7.** Река и два узких места. Мост занимает три клетки: вода в центре, сухие берега по краям. Одна обычная фигура лишняя.

Начальная и конечная клетки всегда проходимы. Обычные плиты нельзя ставить на деревья, камни или воду. Мост вращается целиком на 60°, как остальные фигуры. Победа проверяет только непрерывность дороги по общим сторонам гексов, а не расход набора.

На первом уровне Рута остаётся у дома: готовый путь подсвечивается и появляется «Дорога готова!». На остальных уровнях по пути проходит условный маркер Руты. После завершающей реплики кнопка возвращает на карту. У мельницы запускается колесо. При `prefers-reduced-motion` перемещение происходит сразу, вращение колеса выключено. Во время завершения управление заблокировано от повторного запуска.

## Управление

- **Выбрать и поставить:** выбери фигуру, нажми клетку, при необходимости поверни, затем нажми «Поставить». До первого клика мышь показывает предпросмотр при наведении. Клик фиксирует место: движение к кнопкам не сдвигает фигуру. Другой клик меняет клетку.
- **Перетаскивать:** потяни фигуру из набора или с поля и отпусти. На телефоне опорная клетка выше пальца. Поворот доступен через кнопки. Если сначала нажать на фигуру и повернуть её, для перетаскивания остаётся миниатюра «Тяни отсюда» в строке действий.
- Точка отмечает опорный гекс; у моста он в середине. Недопустимое место — пунктирная красная обводка и знак ⊘. Неудачный перенос и `pointercancel` сохраняют исходное положение.
- Нажатие на уложенную фигуру выбирает весь экземпляр. «В набор» убирает его с поля. «Другие плиты» закрывает предпросмотр; уложенные фигуры сохраняются.
- «Отменить» возвращает предыдущее подтверждённое действие. Escape сбрасывает неподтверждённый предпросмотр; в настройках закрывает только настройки.
- Настройки содержат смену режима, перезапуск, возврат на карту и полный экран, если он поддерживается. Перезапуск не сбрасывает уже пройденные дороги главы.

Целевой экран — телефон 16:9 в альбомной ориентации, начиная с 640×360 CSS-пикселей. На первом уровне сверху расположены карта, помощь и настройки; снизу общий деревянный поднос с оставшимися фигурами. При выборе появляются миниатюра и действия с фигурой; поле не прыгает. В портретной ориентации поднос занимает два ряда. Другие уровни сохраняют прежний интерфейс. Кнопки не меньше 48×48 px. Учитываются `dvh`, safe-area, поворот телефона и размер окна.

## Сохранение и песочница

Завершённые уровни сохраняются в `localStorage` под ключом `ruby-village:chapter-1:v1`. Повреждённая запись или неизвестная версия открывает новую главу. Открываются только последовательные участки. При недоступном хранилище игра работает до закрытия страницы и сообщает об этом на карте.

«Начать главу заново» на карте требует отдельного подтверждения. Обычный перезапуск уровня не стирает прогресс. Расстановка плит внутри незавершённого уровня не сохраняется при выходе на карту или обновлении страницы.

Песочница сохраняет прежние размеры 7×5, 9×6, 11×7 и пять фигур. Переключение размера очищает поле и историю. Песочница не меняет прохождение главы.

## Устройство и доказательства

- `src/hex.ts` — axial/cube-геометрия, вращение, соседство и поиск пути.
- `src/model.ts`, `src/levels.ts` — типы, местность, независимые наборы, реплики и эталонные решения.
- `src/game.ts` — проверки размещения, воды, моста и всей расстановки; связность.
- `src/progress.ts` — версия сохранения, проверка данных и последовательное открытие.
- `src/scene-layout.ts` — общий равномерный масштаб и игровые/source anchors декораций, без отдельных portrait-координат.
- `src/level-art.ts`, `public/assets/level-1/` — иллюстрации первого уровня, статичная Рута и программные трещины плитняка. Все слои используют координаты SVG-поля.
- `src/main.ts`, `src/style.css` — карта, Pointer Events, история, SVG, диалоги и завершение.

Эталонные решения проверяются автоматически. Для первого уровня кратчайший путь по сухим клеткам требует 6 промежуточных клеток, ровно столько содержит набор (3 + 2 + 1). В любом собственном поднаборе клеток меньше 6, поэтому победить им невозможно даже с произвольными одиночными камнями. Эталон укладки всех трёх фигур проверен через `winningPath`. Для сада проверено отсутствие дороги без обхода нижнего края преграды даже при замощении всей доступной земли. Для реки перебраны все допустимые положения моста: есть две переправы между берегами. Дальняя требует минимум **12 замощённых клеток**, даже если разрешить произвольные одиночные камни; всего в наборе **10 клеток**, включая мост. Ближняя имеет допустимое эталонное решение. Уникальность остальных решений не заявляется.

## Проверки

`npm test` — 25 содержательных теста геометрии, размещения, местности, мостов, эталонов, ограничений головоломок и сохранения.

Дополнительные браузерные проверки требуют Python + Playwright и Node на PATH:

```sh
python -m venv .venv
. .venv/bin/activate
pip install playwright
playwright install chromium
# В другом терминале: npm run dev
python tests/browser_check.py
python tests/chapter_browser.py
# После npm run build и npm run preview:
python tests/art_browser.py
# Можно передать URL опубликованной сборки последним аргументом.
```

`browser_check.py` сохраняет проверки обоих режимов песочницы: повороты, перенос, отмена, очистка, недопустимое размещение, pointercancel, фиксация клетки по клику, дорога и смена ориентации.

`chapter_browser.py` проходит три уровня через настоящие элементы управления, проверяет реплики, колесо, открытие участков, перезагрузку, переигрывание, изоляцию песочницы, подтверждение сброса, повреждённое и недоступное хранилище. Проверяет касания, вращение крупных фигур, перетаскивание моста, отмену касания и reduced motion. Проверяет карту и уровни на 1280×720, 915×412, 740×360 и 640×360. Скриншоты — `/tmp/ruby-chapter-*.png`.

## Графика и ограничения

Первый уровень оформлен по [HANDOFF v3](docs/courtyard-v3-handoff.md) поверх привязок v2. Исходные маленький дом, деревянная калитка и Рута не изменены. Старый `meadow.png` остаётся историческим ассетом, но больше не используется на поле.

`src/environment.ts` задаёт землю, параметры декора, интервалы стоек, привязки ограды к крайним стойкам PNG калитки и presets окружения. Земля повторяется с периодом 20 радиусов гекса (10 диаметров), соседние фрагменты зеркальны: края совпадают без квадратных швов. Фон и объекты используют единый равномерный масштаб сцены. В portrait ограда ограничена компактным двором вокруг поля; игровая сетка не транспонируется. Ширина ограничивает размер гексов: сверху и снизу остаётся мелкая трава, а не увеличенные растения.

Новые PNG проверены на траве: мягкие цветные подложки заметны, особенно у секций ограды. Поэтому все шесть новых декоративных PNG используются только как референсы; ограда, низкие кусты, цветники и камни — чистые SVG. Проверка исходных PNG и повторения земли 2×2 сохранена в `docs/screenshots/v3-after/asset-review.png`. Ограда строится по общей цепочке оснований стоек, без дублирования соединений; у калитки используются её собственные крайние стойки. Охристые площадки и тропинка — программные формы с мягким краем. Окружение не меняет проходимость и не перехватывает касания.

Старт — offset(0,1), цель — offset(6,4). Дом примыкает к старту, ноги Руты точно на старте; проход калитки — у нижнего правого края цели. Source anchors сохранены: дом (0.66, 0.93), Рута (0.55, 0.965), калитка (0.50, 0.80). Дом занимает две blocked-клетки и имеет высоту около 2.5 роста Руты. Остальные обычные клетки не закрыты спрайтами. Старт и цель — постоянные проходимые площадки.

Плоский чароит сохраняет угловатые фрагменты, узкие швы и насыщенный фиолетовый цвет. Направление и изгиб прожилок зависят от координат и фрагмента, материал точно обрезается гексом. Наружная кромка — 1.25% высоты гекса; внутренних боковых граней нет. Опорная точка на миниатюрах уменьшена, но сохраняет функцию привязки. Фигуры на подносе — реальные игровые формы.

Схема сохранения главы не меняется: в ней только IDs завершённых уровней, координаты/инвентарь/раскладка не сохранялись. Миграция и сброс не нужны; существующее прохождение сада и мельницы сохраняется. Проверка загрузки старого progress добавлена в браузерный сценарий.

Ходьба пока не готова: черновой GIF не подключён, статичная Рута не перемещается при победе. Для остальных уровней и карты сохраняются условные обозначения. Позже нужны кадры ходьбы/риг Руты, изображения сада и мельницы с отдельным колесом, мест карты, препятствий, воды и моста.

`art_browser.py` проверяет production URL PNG, реальные source anchors через SVG transform, попадание в клетки, размеры кнопок, отсутствие перекрытия обычных проходимых клеток декорациями, перестановку/возврат/вращение/undo/touchCancel, смену ориентации, победу и сохранение прежнего прогресса. Размеры: 1280×720, 844×390, 390×844, 915×412, 740×360. Дополнительно сохраняется landscape 11×7. Скриншоты текущего оформления — `docs/screenshots/v3-after/`; предыдущие версии сохранены в соседних каталогах. Для запуска URL передаётся первым аргументом, папка скриншотов — вторым.

Расхождения с эскизом намеренные: исходный маленький дом, точная point-up сетка, реальный набор 3 + 2 + 1, статичная Рута, упрощённые векторные прожилки. SVG-окружение проще живописного референса. На низком телефоне декор уменьшается ради клеток; в portrait свободная земля остаётся из-за пропорций неизменной сетки 7×5.

Эмуляция не заменяет настоящие устройства: Safari и физические телефоны в этой итерации автоматически не проверялись. Предыдущая песочница 11×7 уже была удобна на телефоне по результатам пользовательской проверки; новые мост и препятствия ещё нужно проверить руками. Сохранение локально для этого браузера и не переносится между устройствами.

## Публикация и работа с задачами

Каждое задание ведём через GitHub Issue, отдельную ветку и PR. Каждый PR проходит ревью, замечания исправляются до слияния. Прямых push в `main` нет.

Текущий `.github/workflows/pages.yml` запускает тесты и сборку. PR проверяется без публикации; после слияния в `main` публикуется `dist` через GitHub Pages. HTTPS включён. Домен `maks.live` унаследован от аккаунта, базовый путь Vite — `/ruby-village/`.


Правила для работы ассистента закреплены в [AGENTS.md](AGENTS.md).
