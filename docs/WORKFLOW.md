# Работа над игрой: ChatGPT → Issues → Codex → PR

## Где хранится контекст

- **Спецификации и утверждённые материалы репозитория** — источник истины о текущей игре. Не заменять их текстом из чата или описанием Issue.
- **GitHub Issues** — конкретные задачи, баги, идеи и история решений. Дополнять существующий Issue вместо создания дубля.
- **Pull Requests** — конкретные изменения, проверки, скриншоты/видео и ревью.
- **ChatGPT** — обсуждение и подготовка материалов. Долговременные решения переносить в репозиторий.

## Как передавать задачу Codex

1. Согласовать задачу и критерии готовности в GitHub Issue (при необходимости приложить референсы в репозитории).
2. Написать Codex: «Выполни Issue #N в этом репозитории. Прочитай AGENTS.md и связанные спецификации. Создай рабочую ветку и PR. Укажи выполненные проверки и приложи визуальные доказательства там, где они нужны».
3. Codex выполняет работу согласно **AGENTS.md**, не заменяя существующие технические и игровые правила.
4. Проверить PR и результат. Замечания и дополнения фиксировать в PR/Issue; обновлять реализацию до принятия.
5. Merge и закрытие Issue — только по правилам AGENTS.md соответствующего проекта.

## Как продолжить после зависания чата

Открыть новый разговор и передать ссылку на репозиторий, актуальный Issue/PR и попросить прочитать спецификации и AGENTS.md. Никаких ZIP с историей переписки не требуется.

## Сохранение решений

Идеи, ещё не принятые, хранить как Idea Issue. Если решение утверждено и меняет долговременный замысел, обновить актуальную спецификацию через PR со ссылкой на обсуждение. Не создавать параллельных конфликтующих «источников истины».

## Важно

Эта инструкция описывает только организацию. При конфликте следовать AGENTS.md и существующим утверждённым спецификациям; самостоятельно не менять правила согласования, ревью и публикации.
