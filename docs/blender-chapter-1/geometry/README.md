# Двор: контракт геометрии

По уточнению Максима внешний вид 3D-кандидата дорабатываем позднее.
Сейчас закрепляем регулярное поле, области препятствий, старт/цель и эталон.

[Схема для просмотра](gate-contract.png) · [SVG](gate-contract.svg) ·
[Входные данные из движка](gate-engine.json) · [Отчёт](gate-report.json).

```sh
node --experimental-strip-types scripts/blender/export-game-geometry.ts gate
blender --background --threads 4 art/blender/gate-pilot.blend --python-exit-code 1 --python scripts/blender/obstacle_contract.py
```

Экспортёр использует настоящие `levels`, `boardCells`, `footprint`, `hexCenter`,
`project` и `scenePoint`. Не переносит приблизительные контуры из рисунка.
После изменений игровых данных сначала нужно заново выполнить экспорт.

Результат — `art/blender/gate-geometry.blend`: 77 замкнутых призм, 16 из них
помечены как препятствия, 61 как доступная земля. Их верхние грани лежат на z=0,
толщина уходит вниз. Это **контурные прокси**, а не готовые модели зданий.
Старые коллекции художественного кандидата скрыты, но сохранены для сравнения.
Якоря start/goal — игровые опорные точки, не переименованные пороги старых моделей.

Проверка читает реальные верхние грани мешей из Blender и проецирует их его камерой.
Затем вычисляет пересечения выпуклых полигонов со всеми игровыми гексами:
каждый запрещённый гекс должен быть заполнен, каждый доступный — свободен.
Это проверка полной площади, а не сетка проб или только центры. Вершины проверяются
дополнительно; общие рёбра могут касаться без ненулевого пересечения площадей.

Результаты gate:

- максимальная ошибка вершины — **0.000082 px**;
- максимальное расхождение площади — **0.01012 px²** при допуске **0.25 px²**;
- удаление одного препятствия обнаруживает дыру примерно **8275 px²**;
- перенос препятствия на доступную клетку обнаруживает лишнее препятствие примерно **8275 px²**.

Последние две проверки намеренно портят данные только в памяти проверяющего кода;
они не записывают повреждённую сцену. Они подтверждают, что проверка ловит и
недостающие, и лишние препятствия.

Заливки схемы взяты из спроецированных Blender-мешей; синий пунктир — независимые
контуры движка. Схема — векторный технический отчёт, не Cycles-рендер и не экран игры.
Фиолетовым показаны семь клеток эталонных плит, зелёным start, оранжевым goal.

**Что ещё не совпадает:** декоративный домик и калитка из первого пилота.
Измерены центр порога на земле и середина закрытой створки: до игровых якорей
около **201 px** и **248 px**. Поэтому успешная проверка прокси не означает,
что старые художественные объекты уже правильно стоят или занимают всю область
запрета. Следующая геометрическая работа — привязать реальные модели к этим пятнам
и входам, сохраняя доступные гексы и полный контур плит. Визуализация после этого
может менять материалы и детали, но не этот контракт.
