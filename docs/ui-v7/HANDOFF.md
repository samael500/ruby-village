Восстановить художественный интерфейс по приложенным референсам v6, включая исправленный портрет Руты. Сейчас окружение рисованное, а интерфейс остался набором простых прямоугольников и градиентов. Наличие кнопок нужного цвета не считается соответствием дизайну.

Это задание на UI: НЕ менять текущие восемь головоломок, поля 11×7, формы и решения, проекцию земли, физику мостов, прогресс или настройки управления ради макета. Примерные формы плит на рисунках не переносить в данные уровней. Не дорисовывать заново окружение.

Соблюдать AGENTS.md: оформить/обновить Issue, создать ветку от актуального main, реализовать и проверить, открыть PR для ревью Максима. Не сливать и не пушить напрямую в main. Этот пакет — результат чтения кода и снимков, игровой репозиторий автором задания не изменён.

## 2. Компоновка игрового экрана
Игровая сцена, HUD и лоток имеют разные области ответственности.
- Сцена занимает доступную высоту до лотка.
- HUD расположен абсолютно поверх сцены, не отнимает отдельную строку высоты.
- Верхняя группа слева: круглая кнопка карты, бумажная плашка названия, подпись «За калитку · N/8».
- Справа: ? и меню из трёх линий. Шестерёнка допустима только внутри настроек.
- Размеры круглых кнопок: 48 CSS px. Отступы: 12–16 px desktop, 8 px phone + safe area.
- Заголовок 20–24 px desktop, 16–18 px phone. Подпись 11–12 px; на коротком экране можно скрыть.
- Плашка компактная, максимум 32% ширины desktop / 42% phone; длинное имя переносится в две строки. Текст не обрезается бессмысленным многоточием.
- Декоративный значок scene-event вынести из основной верхней группы. Он не должен выглядеть случайной третьей кнопкой.
- Сообщение ошибки размещать как небольшую временную бумажную подсказку, не скрывать от зрячего игрока только в aria-live.

Нельзя перекрывать доступные клетки/Руту верхними кнопками: измерить границы HUD, проверить все восемь сцен. При конфликте корректировать компоновку сцены единым масштабом/смещением, не отдельные гексы и не логические координаты.

Фон продолжает contain, сохраняет геометрию. Для свободных краёв использовать тёмный зелёный с мягкой фактурой, край с тенью и редкие крупные силуэты растений. Не заполнять полосы растянутыми домами, зеркальными заборами, резкими копиями сцены. Вода и лес могут иметь своё обрамление. На телефоне улучшить полезный масштаб за счёт удаления отдельной верхней строки; широкие поля не устраняются ценой обрезанной калитки или нечитаемой геометрии.

## 3. Лоток и выбранная плита
Форма/структура лотка из gameplay reference обязательна: неглубокий светлый деревянный край, льняные гнёзда, камень в каждом, мягкая тень.
Desktop ориентир высоты 90–104 px; phone 64–76 px. Это не жёсткий процент: минимум кнопок 44×44, предпочтительно 48×48. На телефоне материал заметен, но рамка не съедает высоту.

Сохранять запас видимым при выборе. Удалить переключение $('tray').hidden=!!selected. Кнопка проверки остаётся на своём месте; при необходимости disabled, не исчезает.
- Выбранное гнездо: тёплая светлая рамка и подъём 2–3 px.
- Невыбранное: спокойная подложка; placed-состояние не должно менять ширину остальных.
- Выбор другой плиты возможен сразу из лотка, без «Другие плиты».
- Вместо ряда «Другие плиты / выбранная / влево / вправо / поставить / в набор» — компактная группа выбранной: поворот, «Поставить» и, если уже на поле, «В набор».
- Одного поворота +60° достаточно; существующие обе клавиши поворота можно сохранить. Не менять правила вращения.
- В режиме drag handle — сама выбранная плита, без отдельной дублирующей большой карточки.
- Справа всегда «Отменить» и «Проверить». Не растягивать их на весь лоток.
- Если камни не помещаются, прокручивается только запас. Группа действий и основные кнопки закреплены. Переключение между drag и select остаётся в настройках.
- Изменение выбора/поворота не сбрасывает положение прокрутки и фокус.
- Когда запас пуст, спокойная подпись «Все плиты на поле» вместо огромной пустой доски.

Размер камней измерять по форме: desktop видимая высота одиночного камня 48–60 px; phone 32–40 px. Составная фигура целиком различима внутри гнезда; клик минимум 48×48. Длинные фигуры допускают более широкое гнездо. Превью ориентировано так же, как поле, и поворачивается вместе с выбранной деталью.

Использовать aria-pressed для рамки и состояния — не параллельный невыставляемый класс .selected.
Заменить белый «якорный» кружок на камне в лотке аккуратной меткой только когда она нужна для управления. Сплошные белые точки на всех декоративных превью не нужны.

## 4. Главное меню
Двор или отдельный чистый фон — настоящая иллюстрация, не радиальный градиент.
Бумажная панель слева, справа видимое окружение. На 844×390 панель максимум около 46% ширины, высота не более доступного экрана; кнопки минимум 48 px.
Порядок: название, «За калитку», основное действие, выбор уровня, настройки, небольшой прогресс.
Новый игрок: «Начать приключение». С сохранением: «Продолжить».
Скрыть общую верхнюю шапку в main menu: название не должно дублироваться.
Прогресс и предупреждение о сохранении живые, без «3 из 8» из макета.
Заголовок и кнопки оформлены тем же материалом и шрифтами, что уровень.

## 6. Пауза, результат, прочие окна
Общий PaperPanel для паузы, результата, помощи, настроек и подтверждений: фактура бумаги, тонкий деревянный край, тёмный текст, мягкая тень, немного листьев по углам.
Пауза — затемнённая текущая сцена, центрированная панель. Кнопки: «Продолжить», «Карта деревни», «Начать заново», «Настройки». Верхний X и Escape продолжают игру. На phone панель помещается по высоте без обрезанных действий.
Результат — «Дорожка готова!», небольшая иллюстрация, короткая реплика и основная кнопка по месту: например «К саду Кролика», второстепенная «На карту». На восьмом уровне — завершение главы, без несуществующего playable продолжения.
Не показывать одновременно диалог и окно победы. После ходьбы: сюжет, затем результат. Не добавлять оценки, валюту или таймер.
Перезапуск уровня и сброс всей главы различать в тексте и подтверждениях. Сброс главы убрать из постоянно видимой главной панели карты в дополнительное меню.
Настройки — тот же стиль. Не показывать включённый звук/музыку, если аудиологики нет.

## 7. Карта
Текущая карта — схематика. В этом UI-проходе заменить Unicode-значки на узнаваемые миниатюры текущих восьми мест, согласовать бумажные подписи и кнопки. Пройдено/доступно/закрыто различать не только цветом.
Повтор реплик открывается через меню места/доступный контрол, а не большой отдельный прямоугольник ▤ рядом с каждым уровнем.
Основные действия: назад в главное меню, выбрать место. Песочница, приглашение и сброс — дополнительные действия.
Не объявлять этот промежуточный выбор уровней полной рисованной глобальной картой. Для неё нужна отдельная согласованная иллюстрация с восемью местами; существующий код карты не заменяет эту работу. Не расширять текущий PR на генерацию и согласование нового мира.

## Порядок реализации и критерий готовности
Сначала новые чистые материалы, затем один реальный игровой экран 1280×720:
HUD + полный лоток + выбранная плита. Приложить рядом оригинальный референс.
После визуальной самопроверки перенести компоненты на остальные состояния и телефон.
Не останавливаться на первом скриншоте: задача включает все перечисленные окна.
PR завершает задачу, когда:
- интерфейс узнаваемо соответствует бумаге/дереву/растениям референсов;
- главное меню имеет иллюстрированный фон и одну панель, без градиентной заглушки;
- выбранная плита выделена, лоток не исчезает;
- диалог показывает правильный крупный портрет только нужному говорящему;
- верхний HUD не занимает отдельный ряд и не перекрывает поле;
- окна результата/паузы/настроек согласованы по материалам;
- регрессии управления, сохранений и ориентации отсутствуют;
- реальные desktop/phone снимки всех важных состояний приложены;
- report.md честно перечисляет оставшиеся художественные пробелы.
Функциональные тесты не подтверждают художественное сходство. Обязателен ручной просмотр рядом с референсами. Не утверждать «полностью соответствует», если заменён только цвет кнопок.
