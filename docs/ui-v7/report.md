# Интерфейс v7

Основа — main ea979d3, задание [#26](https://github.com/samael500/ruby-village/issues/26) и [HANDOFF.md](HANDOFF.md). Изменены интерфейс и материалы; данные восьми уровней, эталоны, проекция, размещение, вода/мост и формат сохранений не менялись.

Плавающий HUD освобождает высоту сцены. Лоток остаётся при выборе, показывает поворот выбранного камня, сохраняет DOM кнопок, фокус и прокрутку. Действия стоят справа; сам камень служит источником перетаскивания. Проверка остаётся на месте, во время выбора недоступна. Главное меню показывает двор и бумажную панель слева; общая шапка скрыта. Диалог занимает нижнюю полосу: крупный погрудный портрет только при репликах Руты, для остальных — имя без чужого портрета. Длинные реплики разделены, письмо имеет прокрутку. Пауза, помощь, настройки, подтверждения и результат используют общие бумажные материалы. На карте появились миниатюры мест; песочница, приглашение и сброс находятся в «Ещё…».

## Проверки

- `npm test`: 40 тестов, все проходят.
- `npm run build`: TypeScript и production-сборка проходят.
- `tests/art_browser.py`: восемь эталонных решений на 1280×720, 844×390, 1024×768 и 1920×1080; проецированные касания, победа, сохранение пропорций фона.
- `tests/art_v6_ui_browser.py`: восемь последовательных побед, сохранение/обновление, переигрывание, сброс, перезапуск с подтверждением, песочница, мышь, сенсорный мост и большая фигура, pointercancel/ошибочное размещение/отмена, пауза движения при перекрывающихся диалоге и portrait-экране, запрет localStorage.
- `tests/ui_v7_browser.py`: перечисленные состояния, постоянный лоток, переключение выбранной плиты, сохранение фокуса и прокрутки при вращении, правильный speaker, видимое сообщение о несоединённой дороге. Все восемь сцен на 1280×720, 844×390, 740×360, 915×412, 1024×768, 1920×1080: доступные клетки не пересекаются с HUD, прокрутки страницы нет. На 740×360 проверен настоящий поток touch-событий для свайпа запаса; на 390×844 — блокировка и возврат без потери расстановки.

Автоматизация — Chromium. Физический телефон и Safari не проверены. На устройстве полезно проверить касание небольших камней, свайп запаса, поворот выбранной фигуры и перетаскивание моста.

## Материалы и расхождения

`public/assets/ui/v7/`: чистые фрагменты бумажной фактуры, дерева и льна взяты из разрешённых референсов; иллюстрация открытой калитки — из референса результата. Погрудная Рута вырезана из `ruta-approved.png`, сохраняет утверждённую внешность. Угловые листья созданы встроенным imagegen с прозрачным фоном. Исходный prompt:

> Create a single clean transparent-background raster asset for Ruby Village, a warm illustrated family fairy-tale 2D game UI. One sparse cluster of broad green leaves with a tiny white five-petal flower arranged around a corner, soft painted shading, muted olive and forest greens, warm light, like the leaves framing parchment menus in a children's village adventure. No paper, no frame, no text, no character, no scene, no rectangular backdrop. The leaf cluster occupies an L-shaped corner with open center so it never obscures interactive content. Real alpha transparency. Production UI corner decoration.

Панели, текст и кнопки — живой DOM, сцены не перерисовывались. Бумажные края и украшения упрощены относительно рисунков: без подвесов, сложной резьбы и индивидуальных растительных рамок. Главное меню использует текущий двор; карта остаётся промежуточной схемой с миниатюрами, а не утверждённой большой картой мира. Портретов остальных жителей нет; нужны согласованные изображения Бельчонка, Ежа, Кролика и других говорящих. Калитка в окне результата — общая иллюстрация восстановленной дороги. Звука и музыки нет.

По последнему уточнению совмещение ограды, земли и поля и замена технических endpoint-маркеров вынесены в отдельное [задание #27](https://github.com/samael500/ruby-village/issues/27) после v7. В этом PR они намеренно не реализованы.
