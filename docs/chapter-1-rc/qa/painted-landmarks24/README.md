# Manual whole-frame semantic landmarks — 24 painted E poses / #36

Independent annotation only. **24 whole 384×416 actors remain unchanged.** Coordinates refer to their original packed-frame pixels, x right / y down. No actor translation, resize, warp, mirroring, rig/runtime change, per-frame height normalization, body fit or FootAnchor proposal was applied. One global scale near 0.94 is preserved only as the source's unverified initialization; it has not been applied to these annotations.

`manual-painted-landmarks24.json` contains all 24 manually inspected frames, uncertainty/visibility, source hashes, explicit native anatomical L/R side references and semantic definitions. `overlay-00..23.png` and `overlays24-sheet.png` are diagnostic composites with rings at the stated uncertainties. Their labels do not modify the source RGBA. `annotate.py` only renders these diagnostic copies from the manually entered coordinate list; it never estimates landmarks from alpha bounds or moves the actor. Run with `--source-root <guides-worktree>` if the local source checkout differs.

- **48 physical ankle values are null:** the joints/bone heads are hidden by opaque boots. The separate `estimatedAnkleCenter` fields contain 46 broad visual guesses of the internal center from the visible boot bend, uncertainty 8–10 source pixels. These are artist proxies, **not observed physical joints or exact native bone correspondences**. Crossing frame 7 has no bilateral estimate.
- **89 visible foot-profile points**, uncertainty 3 pixels: heel means the rear-most visible heel/outsole profile midpoint, toe the frontmost toe-profile midpoint. Neither is an inferred floor contact, bbox-bottom point, sole center, native vertex-region mean, or guaranteed 3D-equivalent landmark. A source-drawn rounded heel/toe has inherent semantic ambiguity.
- In frame 7, the boots overlap and their anatomical assignment at the native crossing is ambiguous, so all four bilateral contour fields remain null. Left toe in frames 8 and 18 and left heel in frame 19 remain null due to overlap/occlusion. The raised left toe in frame 19 is separately visible above the front right boot.
- **22 satchel flap-clasp centers**, uncertainty 3 pixels, are a separate optional image landmark. Frames 10 and 15 are not assigned because the hand/ambiguity prevents a confident center. This is the large gold clasp on the bag, **not a waist buckle**. Every `waistBuckleCenter` and `hip` remains null: neither the belt hardware nor physical hip head is independently visible. A corresponding native belt/satchel feature would require a new explicit source measurement; Hips must not be substituted.

Anatomical side is associated with the native frame/leg phase and visible drawn continuity, not a fixed left/right position on screen. Native `Foot.L` is screen-front/right in the early and late phases and screen-back/left in the middle; frame 7 is left deliberately unresolved rather than guessing a swap.

The source SHA256 set binds all 24 PNGs, packing metadata, native marker dataset, original template and common-scale study. Hashes were rechecked after annotation generation. `diagnostic-point-support.json` confirms a source alpha pixel exists within each contour/clasp point's declared uncertainty (111 points). That is only a raster sanity check: it does **not** validate anatomy, semantic native equivalence, origin registration, support/no-slip, or art acceptance. The manual visual pass used every whole frame and every labelled foot grid, then magnified original-source foot details to refine visible profile coordinates.
