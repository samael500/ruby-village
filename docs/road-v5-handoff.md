# Ruby Village: Рута и плитняк v5

Продолжай существующую v4, прочитай AGENTS.md. Окружение и компоновку сохранить: они теперь одобрены. Меняется только герой и material render дороги. Не менять данные головоломок, progress, endpoints и размеры поля.

## Рута

На пользовательском скриншоте рост Руты меньше высоты клетки; она теряется. Увеличить текущий rendered размер сначала в1.6 раза, затем проверить глазами. Ориентир видимый рост1.0–1.25 высоты гекса для текущей сцены, не прежние1.5–1.9 (фон с домом уже изменился). Приоритет: хорошо читаемый силуэт и пропорция с нарисованной дверью. Подошвы остаются на текущем scene anchor, а не сдвигаются вниз после scale; использовать alpha silhouette bounds, не полный PNG. Рисовать над дорогой и сеткой. Маленькая мягкая нейтральная тень под ногами, вне hit-test. Тонкая тёплая светлая обводка около1CSSpx с мягким падением, не белый sticker border/широкий glow. Можно SVG filter или несколько малых drop-shadow. Проверь на grass и charoite. Не менять лицо/одежду/один ремень сумки, не зеркалить Руту.

## Плитняк

В assets six отдельные512×512PNG: tile-01.png...tile-06.png. Они вырезаны из нового generated atlas; вокруг камня есть цветной полупрозрачный ореол. ОБЯЗАТЕЛЬНО clipPath/Canvas clip к точному гексу. Не показывать квадратный PNG напрямую и не использовать bbox alpha ореола как bbox плиты.

manifest.json содержит sourceRect в пикселях файла и приблизительную inner hex область. Используй sourceRect чтобы каменная поверхность занимала весь игровой гекс, а не уменьшенную фигуру в квадратной клетке. Исходные гексы близки к правильным, но нарисованы генератором, поэтому математическая маска движка остаётся источником истины. Подгонка источника в bbox допустима для текстуры, геометрия/hit-test не деформируется. Не захватить halo вместо края камня. Если тонкая краевая подсветка не совпадает с точным polygon, удалить её из видимого crop небольшим overscan2–3%, наружную игровую кромку рисовать по реальной геометрии.

Каждый variant уже содержит полный раскрой одного гекса: один крупный камень +2–3 меньших. Старую большую текстуру нарезанную произвольными окнами не использовать для cells. Убрать mirror/scaleX(-1)/scaleY(-1): на скриншоте v4 это создаёт симметричные прожилки и ложные швы. Variants выбираются стабильным hash axial coords или pieceId+localCell; не меняются каждый render, не использовать random(). В tray и board один visual seed для одного предмета. Если привязка к предмету — вариант перемещается вместе с ним. Поворот60° вокруг центра допустим, reflection нет. Не делать вращение texture зависимым от drag jitter.

PNG сейчас довольно подробные и контрастные. Сначала проверить при реальном размере клетки. Допустимо мягко снизить saturation10–15%/contrast8–12% через один material layer, сохранив насыщенный фиолетовый и видимость узких швов. Это диапазон visual tuning, не обязательные filter константы. Не размывать стыки до исчезновения и не вводить огромные белые glint markers.

Тонкая наружная кромка1–2CSSpx, минимальная тень. Не кубы, не толстые sidewalls. Adjacent cells full-side contact без травяных gaps, наружные borders группы по возможности без двойной толщины внутренних границ. Швы внутри каждой клетки различимы и не образуют одинаковый повторяющийся/зеркальный узор.
