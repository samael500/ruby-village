Работай в существующем ruby-village, прочитай AGENTS.md и DESIGN.md. v4 заменяет художественные указания v3 для первого уровня; рабочие mechanics/data/progress не откатывать.

Цель — визуально законченный первый уровень с цельным рисованным окружением, читаемой сеткой и натуральным чароитовым мощением. Вначале фиксированный landscape1280×720 как проверочный экран, после него portrait390×844 и landscape844×390. Не внедрять остальные главы/карту/NPC сейчас.

## Этап1: проверочная сцена

Создай в текущем приложении dev-only способ показать один уровень в стабильном состоянии: фон, точная сетка, старт/цель, Рута, 3–4 примыкающих paved клеток, несколько предметов в инвентаре. Не менять save игрока и не помечать уровень пройденным. Используй этот экран для скриншота до включения дизайна во все режимы. Проверяй реальные полигоны/hit-test, а не изображение сетки.

## Геометрия

Для изображения uniform fit transform и для сцены same transform. Header/tray отдельные. Не background-size:100%100%, не отдельный cover. При letterboxing расширить края спокойным цветом/мягкой растительностью, НЕ растянуть картинку. При portrait можно использовать более узкую композицию, но grid остаётся тем же логическим7×5, без анизотропного масштабирования. Для11×7 выбери безопасную область/zoom текущего проекта, чтобы ни одна доступная клетка не была закрыта декором.

Калибровка: fit поле в quiet region. Затем сравни world coords start/goal с doorstep/gate. Один uniform affine transform не гарантирует одновременно две идеальные привязки: это намеренно НЕ обещано. Разрешено соединить существующие точные start/goal с нарисованными площадками короткой постоянной подходной дорожкой вне границ puzzle (визуально поддержанной землёй); она не становится частью решения и не пересекает доступные клетки. Если нужны большие соединения или невозможно разместить поле без перекрытий — отчёт со скриншотом и конкретными координатами проблемы для уточнения artwork. Не молча менять набор, endpoints или форму сетки. Нельзя добавлять новый отдельный дом поверх нарисованного.

Рост Руты подобрать относительно НАРИСОВАННОЙ двери; ориентир рост около0.55–0.7 высоты дверного проёма. Ноги привязаны к старту, не центр PNG. В portrait проверить читабельность фигурки и endpoint; допускается увеличить вместе всю сцену через существующий zoom, а не персонажа независимо на глаз.

## Grid/material/UI

Точные цвета/границы и принципы в DESIGN.md. Пустые клетки обязательно читаются на траве без hover; quiet artwork помогает, но не заменяет contour/fill. Не удваивать общие стороны. На телефоне сохранять CSS толщину линии.

Charoite: использовать растровую фактуру через clipPath/Canvas mask точного полигона. Масштаб material согласован в tray/board. Один стабильный texture transform для группы/мировой системы избегает случайных разрывов прожилок на каждом стыке. Если clip отдельных клеток — общий seed/origin. Не высокие кубы: тонкая внешняя кромка2–4CSSpx максимум на большом поле, ещё меньше на телефоне. Internal seams без дополнительных боковых граней. Не повторять один заметный кусок texture одинаково в каждой клетке; использовать контролируемые offsets или большой общий участок, не random перерисовку кадр-в-кадр. No big white decorative points. White functional origin marker если нужен — только selected/drag, с доступным пояснением.

UI остаётся живым, деревянный tray, compact parchment header, круглый back/help/settings. Не копировать нарисованный интерфейс из старых concept files. Код допустим для точных polygons/icons/UI, художественные окружение и stone material брать из PNG. Тени, градиенты, контуры согласовать с тёплым painterly видом.
